# Word 类型、来源与模板选择

适用于已确定的DOCX交付。公共操作、权限和发布核验遵循本技能主文。

## 已确定 DOCX 交付时的文种与版式

沿用已确定的写作与文件目标。修改或转换前取得真实来源；从零起草不机械索要附件。多成果按实际结果逐项核对，内部读取转换与用户下载交付分开。

按沟通目的判断，不机械匹配词语：

| 用户用途 | document_type | 默认 layout_kind |
| --- | --- | --- |
| 向另一单位商洽、询问或答复的函 | letter | official_document |
| 向有审批权的上级请求批准的请示 | request | official_document |
| 向部门下发、要求落实的任务/会议通知 | notice | official_document |
| 向上级正式报送工作情况的报告 | report | official_document |
| 数字金融研究报告、一般分析文章 | report / article | standard_document |
| 个人待办、项目任务清单 | task_list | standard_document |
| 工作方案 | work_plan | 结合是否正式行文判断 |
| 介绍公文写作、解释“函”的含义、培训示例 | article | standard_document |

用户明确要普通 Word、不要公文排版时，遵从 standard_document；明确要公文版式时遵从 official_document。文种与版式不是同一个字段，例如用户要求普通排版的函仍可 document_type=letter。只说“任务”且上下文无法区分个人清单和正式下发通知时，简短问清用途；已说明主送部门和执行安排时直接起草。缺失事实不凭空补全。

DOCX 新建及完整重建的 artifact_generate / artifact_revise 调用必须同时提交严格三字段 delivery_plan，例如 `{"document_type":"notice","target_format":"docx","layout_kind":"official_document"}`；按所选版式读取对应契约中的完整请求。保格式局部修订已暂停，不提交patch请求。

document_type 仅支持 letter、request、notice、report、work_plan、task_list、article、other；layout_kind 仅支持 official_document、standard_document。这三个字段是工具参数，不作为正文或内部推理展示。生成或完整重建的公文 content 必须使用公文契约中的固定版式，普通文档可用完整正文字符串或 sections/paragraphs 对象；对象不再次序列化为 JSON 字符串。重试保持已确认版式。完整重建提交完整判断与完整正文，改变版式需要用户意图支持；仅需局部调整时提供替换建议，不提交局部修订请求。

模板优先级高于上述默认版式：用户明确选择机构模板时走 template_fill_docx，使用真实已发布且当前授权的 template_version_id；不虚构版本、不自动选择未知模板。固定公文版式的 layout_version 为 bank-official-docx-v1，模板版本为空；不能将它冒充机构模板。

## 选择所需契约

确定版式后，只使用对应的《普通 Word 生成与修订》或《公文 DOCX 交付》契约，不混用两套参数。普通 Word 关注内容层级与阅读体验；公文关注文种、专用字段与固定版式。正文起草或润色方法使用 bank-document-writing，不以选择文件版式替代正文写作。

## 来源与续聊

“生成 Word”沿用刚确认的正文和用途，不重新问标题或文种，不先返回大纲等待确认。内容足够时直接生成。用户上传的文件不是已生成成果：用户接受生成新稿时，先完整读取，再用 artifact_generate 生成新稿；Word完整内容修订使用工具真实返回的 source_generated_file_id。不把修订建议或摘要当作完整正文。

### 操作前说明实际处理方式

在开始文件操作前，用简短自然语言说明本次是新建/重新生成、格式转换或指定模板填充；说明的是实际将执行的方式，不只说“处理文件”。目标和处理方式已经明确时直接执行，不为这段说明重复索要确认。

| 实际方式 | 能力与保留边界 |
| --- | --- |
| 重新生成Word修订稿 | 按完整修订正文重新排版，原件保留；任意原样式、图片、图表、批注、修订痕迹、页眉页脚及嵌入对象不保证保留。已有成果修订显式传revision_mode=rebuild，不能称为“原样修订”。 |
| 原件局部修改 | 已暂停，包括平台成果；提供已读位置、原文和替换建议，由用户在Office/WPS中编辑，不交付保格式修订副本。 |
| DOC转DOCX或Word导出PDF | 使用受控转换，原件保留；转换不等于修订或完整读取，也不证明复杂版式、公式和对象完全一致。保持用户要求的目标格式。 |
| 指定机构模板填充 | 仅使用已发布、已授权模板中的指定占位符；模板填充不是任意原件局部编辑，也不保证改写段落内所有混合样式不变。 |

不要将操作方式写入正文或暴露内部字段。最终回复依据实际报告说明完成的方式及已知限制；不因文件已发布就省略重建边界。

普通Word的quality_warnings属于可交付成果的呈现提醒：依据实际代码说明页码、重复表头或段落样式情况，不能推断正文丢失。正文缺失/顺序错误、文件损坏及用户明确的公文版式仍不能以提醒代替失败。

## 文件参数失败后的恢复

生成或完整重建 Word 时把完整正文直接放入 content 对象（paragraphs/sections 或指定公文结构），不要手工拼接或二次 JSON 编码。一次调用必须同时包含正文、文件信息和所需 delivery_plan，不能先调用只有文件名的半成品参数。收到局部修订暂停提示时立即停止，提供修改建议；未经用户接受不改为全文重建。收到 JSON 不完整或结构校验错误时，重新构造完整对象并正确转义正文引号，按具体诊断和剩余恢复预算修正；不允许恢复或无实质进展时说明未生成，不重复播报准备生成，不换工具绕过校验。

## 已有文件转换

将上传的旧版 Word 转为可读取的 DOCX。转换成功后使用实际返回的附件引用读取；若未返回可读引用，只说明转换已完成、读取未完成，不猜文件路径或配对引用，也不反复转换试探文件名。

### 转换与模板问题的下一步

| 实际诊断 | 下一步 |
| --- | --- |
| DOC转换器缺失或转换失败 | 说明本次未取得转换文件、原件保留；可用Word/WPS另存为DOCX后上传，并核对图片、批注和复杂版式，或联系管理员恢复转换服务。不自动重写为普通Word，不把另存为可用视为已保证无损。 |
| 转换或模板权限未开放 | 说明当前助手缺少相应能力，联系管理员确认授权；不换工具、路径或模板绕过。 |
| 指定模板不可用 | 说明未生成模板稿；从当前获授权的已发布模板中重新选择，或请管理员恢复指定模板、文件及绑定。不猜版本，不擅自换成普通Word或其他模板。 |
| 缺少模板填充内容 | 复用上下文已有内容，只补充或询问实际缺少的必填项，然后继续同一模板；不把空白、空列表或占位文案当作已填写，不补造事实，也不让用户填写内部编号。 |

```json
{"source_type":"session_file","source_id":"uploaded_doc_example_only","target_format":"docx","purpose":"read","output_name":"转换示例.docx"}
```

直接 PDF 的 Markdown 表格支持按内容计算列宽、纵横混排、分组与重复表头；Office 导出 PDF 保留原文件版式。


## 已有Word的修改建议与重新生成

所有 Office 文件的保留原格式局部修订已暂停，包括上传附件、个人文件及平台生成成果。这是内部能力边界，不向用户说“暂停局部修订”。对用户说明：“我可以提供修改位置和替换内容，方便你在 Office/WPS 中编辑；如果接受重新排版，也可以生成完整新稿。”只有实际尝试未交付时才说明“这次没有生成修订文件，原文件保持不变”。用户要求改标题、文字、单元格或公式时，先说明当前不能直接交付保格式修订文件；依据实际读取范围提供“位置—原内容—建议内容”，由用户在 Office/WPS 中编辑。不得继续提交局部修订，也不改用脚本、转换副本或其他工具绕过。只有用户明确接受重新排版和完整新稿时，才进入重新生成；“只改一处、其他不变”不等于接受重建。
