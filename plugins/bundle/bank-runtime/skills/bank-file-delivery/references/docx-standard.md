# 普通 Word 生成与修订

适用于已确定 standard_document 的 DOCX 交付；先按《Word 类型、来源与模板选择》确定用途、真实来源及模板优先级，公共权限与发布核验遵循技能主文。

普通 Word 完整参数示例（示例正文仅用于说明结构，实际用当前确认稿替换）：

```json
{"artifact_type":"docx","title":"工作说明示例","content":{"sections":[{"heading":"工作安排","heading_level":1,"paragraphs":["测试完成后，各组汇总结果并提交测试记录。"]}]},"output_name":"工作说明示例.docx","delivery_plan":{"document_type":"article","target_format":"docx","layout_kind":"standard_document"}}
```

普通 sections 可用 heading_level（1–6 的整数，默认 1）表达标题层级。tables 使用等列二维数组，首行为表头；普通 Word 宽表自动横向分节，过宽时分组并重复首列，长行允许跨页、表头重复。不要为容纳表格删列或把正文缩成摘要。

## 普通 Word 的内容组织与成品质量

以下仅适用于已确定的普通 DOCX 交付。根据读者、用途及用户明确的篇幅安排内容；复用已确认稿件，不为套版式重写事实或新增结论。报告、方案等较长材料可先组织完整内容，再一次提交生成；短说明无需扩写成报告，也不增加逐章确认。

需要标题、列表或表格排版时，使用现有 sections/paragraphs/bullets/tables 对象：heading 与 heading_level 表达层级，paragraphs 保存连贯正文，bullets 用于真正并列的事项，tables 用于便于比较的项目。普通正文字符串按字面保留，Markdown 的 #、** 和竖线表格不会自动变成 Word 排版；技术示例中的这些字符则应原样保留。不要传未支持的字号、主题、图片、图表或任意样式字段。

内容开头直接说明主题、主要结论或要办理的事项，后续给出依据、条件和必要细节；按任务需要组织，不强制固定章节。数值保留单位、期间、口径和来源中的不确定性；材料不足时说明缺口，不虚构数据、引用、署名或承诺。表格用于比较或明细，不把整篇文章塞入单元格。正文与表格互补，避免重复堆砌相同内容。

生成前核对实际提交的完整正文是否保留用户要求的各项内容、数字、限制条件和有效来源；这是本轮内容检查，不代表已经完成视觉验收。普通版式由生成器统一设置中文字体、标题与段落间距、表格留白及页码；公文和机构模板仍按各自规则执行。工具确认发布后核对文件引用，未经实际查看不声称“逐页检查通过”或“排版完全无误”。

## 修订与交付核对

先按《Word 类型、来源与模板选择》的操作方式与保留边界处理。用户接受重新生成修订稿时，取得实际完整原稿，核对变更项与未修改项，再提交完整修订内容；已有成果传revision_mode=rebuild。仅改指定正文或表格文字时优先按docx.md的docx_patch契约局部修改，保留其余部分；不把完整重建称为局部修改。

生成器会核对实际DOCX与本次提交稿的正文顺序、段落层级、列表及表格内容，失败时不交付该结果。这不证明提交稿与原稿的未改部分一致，也不代表事实准确或已逐页检查；上述内容核对仍在写作和修订阶段完成。工具成功后确认真实文件引用；实际发现空白页、表格溢出或缺段时说明具体问题并按允许的恢复流程处理，不把“可打开”当作全部质量要求已满足。

## 普通 Word 参数恢复

运行时仅在尚未提交成果操作、无来源文件的普通 Word 参数生成异常时，可触发一次正文恢复。只有收到该恢复指令才采用其短元信息与完整正文格式；正文仍须满足原主题、篇幅和事实要求。程序组装后的请求继续经过原有权限、参数校验和成果发布流程；草稿返回不等于文件已生成，不能降级公文、改用未授权模板或把内部元信息展示给用户。
